EVENTAGENCIES — СБОРКА И ЗАКРЫТЫЙ ХОСТИНГ

ИСТОЧНИК И ДОСТУП
Кандидат релиза основан на выбранной владельцем линии eventagencies-light
с прежнего локального порта 8781: вертикальная фотолента с инерцией, каталог,
профили, галереи и «Мой проект». Stories/Moments и прежняя motion-копия
не являются источником этого кандидата.

Рабочий адрес: https://eventagencies-motion.racinggiant1.chatgpt.site
Основные маршруты: /catalog, /my-project, /admin.
Текущий доступ Sites — только аккаунт владельца. API требует идентификатор
вошедшего пользователя; заявки, история и копии проекта разделены по нему.
Манифест конкретного развёртывания создаётся отдельно от этих инструкций.

КОМАНДЫ И РЕЗУЛЬТАТ СБОРКИ
Команды выполняются из корня проекта. Для локальной версии нужен Node.js 24+.
Для сборки Worker из чистой копии исходников сначала выполните
npm run install:ci — установка зависимостей по package-lock.json.
Для загрузки зависимостей нужен доступ к настроенному npm registry.

npm run build:local — собрать страницы в local-dist.
npm run start:local — пересобрать local-dist и запустить Node-сервер с SQLite.
По умолчанию адрес http://127.0.0.1:8781; другой порт задаётся переменной PORT.
start.ps1 — Windows-запуск локальной версии со сборкой и открытием браузера.
После обновления исходников уже работающий локальный сервер нужно перезапустить.

npm run build — подготовить страницы в .sites-build/static и собрать
Cloudflare Worker с ресурсами для Sites в dist. Worker: dist/server/index.js;
конфигурация: dist/server/wrangler.json; статические ресурсы: dist/client.
Это отдельная сборка от local-dist.
npm start — локальный запуск собранного Worker через Wrangler с локальным D1
и состоянием в .wrangler/state; необходима применённая локальная схема D1.
Эта команда не публикует сайт и не подключает локальный процесс к облачной базе.

ДАННЫЕ И МИГРАЦИИ
Облачный сервер — Worker + D1 через Sites. Локальный сервер — server.mjs,
Node.js 24+ и private-data/inquiries.sqlite3. Эти базы независимы; локальные
заявки, пароли и сессии не импортируются в облако и не входят в архив сайта.

Черновики и заметки остаются в браузере. В D1 явно сохраняются копии проекта
и принятые заявки; исходный снимок заявки отделён от её обработки и истории.
Автоматической доставки сообщений агентствам или клиентам нет.

Облачная схема описана в db/schema.ts; миграции находятся в drizzle:
0000 — заявки и история; 0001 — данные рабочего процесса;
0002 — копии проекта в аккаунте.
После изменения схемы создавайте новый файл командой npm run db:generate.
Уже опубликованные SQL-миграции не редактируются. Новая миграция должна
сохранять существующие данные; локальная SQLite и облачный D1 обновляются
своими механизмами, перенос одного файла базы не заменяет миграцию другого.

ИСХОДНИКИ И АРХИВ
Основной GitHub origin и source repository Sites используются отдельно.
При подготовке развёртывания сборка dist связывается с отправленным коммитом
source repository Sites. Коммиты, архив и идентификатор развёртывания фиксируются
в отдельном манифесте релиза; README не подтверждает публикацию нового кандидата.
Конфигурация проекта Sites находится в .openai/hosting.json.

Сохранён исходный браузерный билд Motion Folio. Его оригинальные React/TypeScript
исходники не восстанавливались. Облачная сборка исключает восемь неиспользуемых
демонстрационных галерей шаблона; их файлы остаются в исходниках и локальной сборке.
